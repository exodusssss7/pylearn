# PyPerky v1.4

Python from zero in small, interactive steps.

## Unit 1
11 lessons: Say hello, Words & quotes, Numbers, Variables, Text + numbers, True or false, If, Else, Repeat with for, Counting with range, and a Countdown mini project.

Every lesson begins with a plain-language concept introduction and a symbol guide. Lessons include common mistakes, worked examples, live Python runs, output prediction, code blanks, tap-to-order code and typing challenges. Start any unit or lesson, or follow the suggested order. Skipping ahead shows a non-blocking suggestion to complete earlier lessons first. Search the course map using standard Python topic names. Progress, XP and day streak are saved in this browser.

## Limits
Twelve units are available, not a complete Python course. Typed challenges check Python syntax-tree structure, not exact message wording. Different messages, spelling and capitalization inside strings are accepted. Python instruction names and variable references still follow Python case rules. These checks are educational, not a proof that every possible solution is correct. Hints are available after mistakes; automatic easier replacement exercises are not implemented. Files use a real but temporary Python filesystem, reset on each Run. They are not saved to the device or available for download. Text-output playground only: no graphics or package installation. input() reads from a local answer sheet before execution, not a live terminal dialogue. Python downloads from jsDelivr on first use, so internet is required. Clearing browser storage removes progress. There are no accounts, cloud sync, backend or paid services. See SECURITY.md for the v1.3 security review and remaining limits. Not a secure sandbox for other people's untrusted code.

## Built with
Plain HTML, CSS and JavaScript; Pyodide 0.29.0 in a Web Worker; locally served Nunito fonts. Hosted on GitHub Pages.

## Practice and audio
Ninety-one guided skill cards plus a free-code playground. Mistakes get specific guidance for quotes, parentheses, names and indentation. Correct answers in a row raise the same chime along a major scale, capped at one octave to avoid shrill pitches. A wrong answer resets it; the streak is per session. Tap, retry and completion keep separate effects. Sound can be muted in Profile; the setting stays on this device. Effects: Kenney Interface Sounds, CC0, downloaded from https://opengameart.org/content/interface-sounds . Original license is included in audio/LICENSE.txt. These are pre-produced interface effects, not claimed to be field recordings.

## Block companion
Original PyPerky SVG/CSS artwork reacts to correct answers, retries, combos, code runs and completion. Character motion uses transform and opacity, follows the display refresh rate, and respects reduced-motion preferences. Actual frame rate depends on the device. No LEGO artwork, branding or affiliation.

## Unit 2
10 lessons: joining strings, character counts, string indexing, making lists, list indexing and length, replacing an item, append, list loops, nested conditions, and a guest-list project. Lessons introduce terms before using them; existing progress is preserved.

## Unit 3
11 lessons: updating variables, subtraction, equality, comparison boundaries, elif, and/or/not, while, break, and a while countdown project. Conditions and updates are taught before while loops.

## Unit 4
8 lessons: defining and calling functions, reusing calls, one and two parameters, return values, local variables, calling a function in a list loop, and a reusable welcome-maker project.

## Unit 5
8 lessons: dictionaries, key lookup, updating entries, adding keys, membership checks, get with a fallback, looping over keys, and a profile-card project. Dictionary entries use string keys and values in these first exercises.

## Unit 6
9 lessons: real input, prompts, digit text versus numbers, int, float, str, multiplication, division, and a snack-bill project. Typed input code opens an answer sheet; each line is consumed by a real Python input() call. Example runs supply named sample answers. Answers are not persisted or sent to a backend. Invalid conversions and missing input get specific feedback; targeted exception handling follows in Unit 8.

## Unit 7
7 lessons: writing and reading text files with with/open, newline escapes, append mode, line iteration with print(end=""), counting lines, and a two-entry notebook project. Each Run starts with an empty temporary Python workspace, not device storage.

## Unit 8
7 lessons: ValueError, continuing after recovery, try/except/else, finally, FileNotFoundError, separate handlers for conversion and zero division, and a safer number-reader project. Input is still supplied before execution rather than through a live terminal.

## Unit 9
8 lessons: classes and instances, instance attributes, methods and self, __init__, method parameters, return values, separate object state, and a two-buddy project. These are first class steps, not a complete object-oriented programming course.

## Unit 10
6 lessons: lists of dictionary records, nested lookup, record loops, additions/updates, filtering and a page total.

## Unit 11
6 lessons: modules, math.sqrt and math.ceil, explicit from imports, aliases, json.dumps and json.loads. Only included standard-library tools are taught; arbitrary third-party packages are not installed.

## Unit 12
A five-stage reading-tracker project: instance storage, a total method, one validated input addition, a JSON practice-file round trip, and the combined report. Files remain temporary and input uses the pre-run answer sheet. This completes the current beginner path, not the whole Python language. JSON examples decode data created by the same program, not arbitrary untrusted uploads.

## App polish in v1.0
A Continue card opens the next unfinished lesson; the course map expands by unit. Python editors keep local drafts and offer indentation, newline, punctuation and copy controls. Input answers are not saved. Practice skills can be searched. Running code can be stopped, and the Python worker restarts for the next Run. Sound assets load on interaction rather than startup. Background motion and mobile blur effects were removed; optional mascot and correct-answer motion still respect reduced-motion preferences. Actual phone frame rate depends on device and browser. Lesson count remains 96.

## Topic navigation in v1.1
Unit and lesson titles use standard Python terms. The course search finds units and lessons by topic, including loops, functions, classes and exception handling. Every lesson is open from the start, with a friendly suggestion when earlier lessons are incomplete. Existing progress and drafts keep their original IDs.

## Ranks in v1.2
Ranks use unique completed lessons: Bronze (0), Silver (5), Gold (15), Platinum (30), Diamond (50), Master (75), Legendary (96). Existing completed lessons count automatically. Replays still earn XP but do not advance rank. The header badge opens rank details, and crossing a threshold at lesson completion shows an original SVG badge reveal and a rising four-note chime made from the existing CC0 effect. Mute and reduced-motion preferences are respected. Rank animation changes transform and opacity only; actual phone frame rate depends on the device.

## Rank-meter audio in v1.3
Each first-time lesson completion plays a rising rank-fill sample while the meter advances, including completions that do not change tier. The sample is an adapted/time-stretched maximize_005.ogg from Kenney Interface Sounds 1.0, CC0. A promotion adds the four-note chime after the fill. Replays do not fill the rank meter. Mute applies to both effects. The source is pre-produced interface audio, not claimed to be a real-world field recording.

## PyPerky name and logo in v1.4
The original brick companion is the app logo, favicon and install icon. It is not LEGO artwork and has no LEGO affiliation. Repository and site path remain pylearn so existing links are not moved. Internal browser keys (pylearn-v1, pylearn-sound, pylearn-draft-*) and lesson IDs are intentionally unchanged to preserve progress. The same-origin browser data is still local to the device.

## Responsive layout

The app fills the available viewport. Phones use a single column, tablets show a wider course grid, and desktop screens put the course or editor beside its context. Navigation stays outside the scrolling content. Safe-area padding and the visual viewport keep controls reachable when a keyboard opens. Progress keys and the existing Pages address stay unchanged.
